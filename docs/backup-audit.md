# 設定保存・バックアップ点検

## 修正内容

- 信頼ユーザー／ロールIDは入力中の区切り文字を保持し、保存時に配列へ変換する。
- 保存応答で入力中の変更を消さず、古いサーバー読み込み応答を現在の画面へ混入させない。
- 自販機の保存・読み込み中は編集を止め、別自販機への切り替え時に旧データを保存しない。
- 設定値の型・整数範囲・ID配列を検証し、不正値を黙って変換／欠落させない。
- AutoModは既存ルールを更新し、作り直す前に有効な保護を削除しない。Discord適用失敗は保存結果と分けて通知する。
- バックアップ本体・分割データをD1の同一バッチで保存する。DB読み取り失敗を空データとして記録しない。大量商品の取得はバインド数を制限する。
- 同一サーバーでは元IDを優先し、同名ロール・チャンネルを一対一で復元する。プレビューにも同じ区別を反映する。
- 各復元項目の進捗を保存し、Cronの重複実行をDBリースで防ぐ。キャンセル後に状態を上書きしない。恒久的なDiscordエラーは失敗として停止する。
- 復元中のバックアップの削除、および別バックアップの二重復元開始を防ぐ。
- 現在DBにある在庫（販売済み・予約中を含む）は復元で複製しない。別サーバーに元在庫が残る場合も二重販売を避けて複製しない。
- すでに在籍するメンバーのロール・ニックネームはOAuth再参加なしで復元する。未在籍者の再参加には従来どおり事前OAuth登録が必要。
- ロール／チャンネル位置、メンバーロール、ニックネーム、AutoModの復元失敗を警告に残す。警告付きの完了を画面で区別する。

## 再現・検証

```sh
npm ci
npm run build
npm test --workspace @dsm/worker
npm test --workspace @dsm/web
```

WorkerはMiniflareと実際のローカルD1を使用し、Discord APIは状態を持つテスト応答に置き換える。空／既存DB、認証、権限、暗号化、分割保存、復元の再実行、同名項目、在庫重複、キャンセル、権限拒否、DB障害、並行処理、設定保存を確認する。

画面は実際のReactコンポーネントをDOM環境で操作し、逐次入力・保存中の変更・再マウント後の値・バックアップ作成フォームを確認する。これらは実Discordサーバーへの破壊／復元テストではなく、決済も実行しない。

## 検証範囲の限界

実Discordサーバーの消失からの全面復旧、実ユーザーのOAuth再参加、実決済、全チャンネル種類と全権限構成、大規模サーバーでの実際のレート制限はこの自動テストだけでは保証しない。復元は既存項目を削除しないため、追加済みの余分な権限や項目を完全に巻き戻す機能ではない。Discord API成功直後かつ進捗保存直前のプロセス終了には、分散システム上の再実行余地が残る。
